# 4장 · 도구

> 도구는 에이전트의 손발이다. 도구 분류와 일반 설계 원칙, MCP 프로토콜과 도구 선택의 과제, 인식·실행·협업 도구, 이벤트 기반 비동기 에이전트를 다룬다.

← [메인 README로 돌아가기](../README.md) · 📖 [장 본문 읽기](../book/chapter4.md)

## 부속 프로젝트

| 실험 | 프로젝트 | 유형 | 설명 |
| :--: | --- | :--: | --- |
| 4-1 | [perception-tools](perception-tools/) | ✅ | 웹 검색, 멀티모달 이해, 파일 시스템 조작, 공개 데이터 소스 접근 기능을 포괄하는 인식 도구 모음을 구축한다. 기능 대부분은 무료 공개 API(DuckDuckGo, Open-Meteo, Yahoo Finance, OpenStreetMap 등)를 사용하며 API 키가 필요 없다. |
| 4-2 | [execution-tools](execution-tools/) | ✅ | 파일 조작, 코드 인터프리터, 가상 터미널, 외부 시스템 연동을 포함하는 안전한 실행 도구 모음을 구현한다. 보조 LLM 승인 메커니즘으로 위험한 작업을 막고, 복잡한 출력을 자동 요약하며, 코드 문법을 검증한다. |
| 4-3 | [collaboration-tools](collaboration-tools/) | ✅ | 브라우저 자동화(browser-use 프레임워크), 휴먼 인 더 루프(Human-in-the-Loop), 다중 채널 알림(이메일, Telegram, Slack, Discord), 타이머 관리를 포함한 종합 협업 기능을 제공한다. 민감한 작업의 관리자 승인과 예약 작업 실행을 지원한다. |
| 4-4 | [agent-with-event-trigger](agent-with-event-trigger/) | ✅ | FastAPI로 만든 현대적인 이벤트 기반 에이전트다. 앞의 MCP 서버 세 개에 있는 모든 도구를 기본으로 통합한다. 네이티브 비동기 아키텍처로 MCP 도구를 깔끔하게 로드하고 HTTP API를 통해 웹, 인스턴트 메시징, GitHub, 타이머 등 여러 출처의 이벤트를 받는다. 자동 API 문서(Swagger UI)와 백그라운드 모니터링 기능을 제공한다. |
| 4-5 | [async-agent](async-agent/) | ✅ | 단일 스레드 asyncio 모델을 바탕으로 이벤트 기반 비동기 에이전트 프레임워크(Flux)의 핵심을 구현한다. 받은 편지함 이벤트 큐가 긴급도(중단/즉시/대기열)에 따라 작업을 배분하고, 비동기 도구 병렬 실행, 실행 중 현재 턴 중단, 모의 장기 실행 작업의 취소와 상태 조회를 지원한다. 실제 LLM의 함수 호출로 의사결정한다. |
| 4-6 | [active-tool-discovery](active-tool-discovery/) | ✅ | ‘120개가 넘는 도구 스키마를 모두 주입’하는 방식과 ‘능동적 온디맨드 탐색’ 방식을 비교한다. 후자는 시스템 프롬프트에 몇 가지 기본 도구와 `discover_tools` 메타 도구만 두고, 임베딩 유사도로 도구 라이브러리에서 가장 관련성 높은 전문 도구 3~5개를 검색한다. 토큰을 절약하고 너무 긴 목록 때문에 모델이 범용 도구를 잘못 선택하거나 오용하는 문제를 막는다. |
| — | [active-tool-selection](active-tool-selection/) | ✅ | 에이전트가 미리 정해진 도구 집합을 수동적으로 받아들이는 대신 작업 요구에 따라 가장 적합한 도구 조합을 능동적으로 고르는 지능형 도구 선택 메커니즘을 구현한다. |

> 또한 `chapter4/docker-compose.yml`과 `chapter4/DOCKER_DEPLOYMENT.md`에는 앞의 MCP 도구 서버를 컨테이너화하고 배포하기 위한 참조 솔루션이 있다.
