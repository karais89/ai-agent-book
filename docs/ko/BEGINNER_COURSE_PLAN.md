# AI 에이전트 입문 코스 구축 계획

## 1. 문서 목적

이 문서는 기존 『AI 에이전트 깊이 이해하기』의 전체 원문을 보존하면서, 처음 접하는 개발자가 원문을 선형으로 읽지 않아도 핵심 개념을 익히고 작은 에이전트를 완성할 수 있는 입문 코스를 구축하기 위한 실행 기준이다.

입문 코스는 기존 책의 축약본이나 목차 요약이 아니다. 다음 세 경험을 서로 분리해 제공하는 별도의 학습 경로다.

1. **입문 코스**: 핵심 개념을 순서대로 학습하는 자기완결형 과정
2. **누적 프로젝트**: 같은 환불 에이전트를 단계별로 개선하는 실습
3. **원문과 실험실**: 더 깊이 탐구할 독자를 위한 선택 자료

이 계획의 구현 과정에서 기존 `book/`, `book-en/`, `chapter1/`~`chapter10/` 원문과 실험 코드는 삭제하거나 입문 코스에 맞춰 재작성하지 않는다.

## 2. 대상 독자

필수 사전 지식은 다음으로 제한한다.

- Python 기본 문법
- JSON 데이터의 기본 구조
- 터미널과 파일 경로에 대한 기초 경험

다음 지식은 필수로 요구하지 않는다.

- Transformer 내부 구조
- KV 캐시와 어텐션 수학
- 강화 학습
- 벡터 데이터베이스
- 분산 시스템
- 실제 LLM API 사용 경험

## 3. 학습 성과

입문 코스를 마친 학습자는 다음을 수행할 수 있어야 한다.

1. 챗봇, 결정론적 워크플로, 에이전트를 구분한다.
2. 모델, 컨텍스트, 도구의 역할을 실제 구성 요소에 대응시킨다.
3. 도구 호출 요청, 실행, 관찰, 다음 결정으로 이어지는 루프를 읽는다.
4. 결정에 필요한 컨텍스트와 불필요하거나 위험한 컨텍스트를 구분한다.
5. 읽기 도구와 상태 변경 도구를 위험도에 따라 설계한다.
6. 권한, 사용자 확인, 멱등성, 사후 검증, 재시도, 종료 조건을 적용한다.
7. 결과와 실행 궤적을 함께 평가하는 고정 평가 세트를 만든다.
8. 실패 원인에 따라 지식, 지침, 코드, 모델 중 수정 위치를 선택한다.

## 6. 공통 누적 프로젝트

### 6.1 프로젝트 이름

**Mori Shop 주문·환불 지원 에이전트**

### 6.2 대표 사용자 요청

> 지난주 받은 블루투스 이어폰을 환불해 줘.

### 6.3 고정 데이터

- 고객: `C-102`
- 주문: `O-1042`
- 상품: 블루투스 이어폰
- 결제 금액: 89,000원
- 배송 완료: 5일 전
- 첫 요청에는 환불 사유가 없음
- 후속 설명: “왼쪽 이어버드가 작동하지 않아요.”

### 6.4 정책

- 단순 변심·미개봉 상품: 배송 후 7일 이내
- 제품 결함: 배송 후 30일 이내
- 사용한 디지털 상품: 환불 불가
- 100,000원 초과 환불: 직원 승인 필요

### 6.5 도구

1. `find_orders(customer_id, date_range)`
2. `get_order(order_id)`
3. `search_refund_policy(category, region, as_of)`
4. `quote_refund(order_id, reason)`
5. `request_user_confirmation(summary)`
6. `create_refund(order_id, amount, idempotency_key)`
7. `get_refund_status(refund_id)`
8. `escalate_to_human(reason, evidence)`

### 6.6 성공 조건

- 대상 주문과 상품이 정확하다.
- 환불 사유와 적용 정책이 확인되었다.
- 환불 가능 여부와 금액이 정확하다.
- 사용자가 대상과 금액을 명시적으로 확인했다.
- 중복 처리 없이 환불이 한 번만 생성되었다.
- 환불 ID와 실제 상태를 다시 조회한 뒤 완료를 보고한다.

필수 과정은 외부 서비스나 API 키가 없는 결정론적 로컬 시나리오로 제공한다.

## 7. 공통 수업 패턴

각 모듈은 다음 순서를 사용한다.

1. 실패 장면
2. 결과 예측
3. 30초 핵심
4. 개념 설명
5. 가이드형 인터랙션
6. 변경 전후 실행 흔적 비교
7. 고장 주입 또는 새 상황 적용
8. 퀴즈와 즉시 해설
9. 모듈 체크포인트
10. 선택형 원문·실험 링크

### 7.1 모듈별 콘텐츠 예산

- 순수 본문: 3,500~4,500자
- 순수 읽기: 10~15분
- 인터랙션과 퀴즈 포함: 25~35분
- 학습 목표: 1~2개
- 새 핵심 개념: 최대 5개
- 새 약어: 문단당 최대 1개
- 그림: 1~2개
- 표: 최대 1개
- 화면에 노출하는 코드: 블록당 25줄 이하, 모듈 전체 40줄 이하
- 인터랙션: 최소 1개
- 퀴즈: 4~5문항
- 외부 인용: 본문 최대 3개, 나머지는 더 읽기로 이동
- 반드시 기억할 문장: 1개

### 7.2 편집 원칙

- 한 문단에는 주장 하나만 둔다.
- 모든 개념은 정의, 예시, 경계 또는 반례 순서로 설명한다.
- 영어 원어는 처음 한 번만 병기한다.
- 굵은 강조는 500자당 한 번 이하를 목표로 한다.
- 제품명, 가격, 리더보드, 최신 프리프린트는 핵심 원리와 분리한다.
- 실험 상자는 모듈당 하나만 노출한다.
- 숨은 사고의 연쇄는 교육 데이터로 표시하지 않는다.
- 입력, 선택한 행동, 도구 결과, 검증 상태, 짧은 결정 근거만 보여 준다.
- 강한 주장에는 다음 성격 레이블을 붙인다.
  - 기본 원리
  - 실무 권장
  - 저자의 관점
  - 최신 연구
  - 제품 사례

- 책과 코스의 전체 지도를 이해한다.

- 하네스는 모델의 결정을 제약하고 검증하며 실패에서 복구시킨다.

#### 결과물

- 학습 경로 선택
- 입문 과정 시작 또는 관심 분야 원문으로 이동

## 9. 퀴즈 설계

퀴즈는 용어 암기보다 적용과 진단을 중심으로 한다.

- 시나리오 분류
- 단계 순서 배열
- 다음 도구 호출 선택
- 최소 충분 컨텍스트 선택
- 위험 등급 분류
- 실행 흔적에서 실패 지점 찾기
- 평가 대시보드 해석
- 실패와 수정 위치 연결

모든 문항은 다음을 가져야 한다.

- 안정적인 고유 ID
- 질문
- 선택지 또는 상호작용 조건
- 정답
- 오답별 또는 선택별 해설
- 관련 모듈
- 난이도

## 10. 기술 설계

### 10.1 구현 형태

- 프레임워크 없는 Web Component와 순수 JavaScript를 기본으로 한다.
- MkDocs Material의 페이지 전환과 충돌하지 않도록 Shadow DOM 또는 범위가 제한된 CSS를 사용한다.
- `navigation.instant`에 대응해 초기 로드와 `document$` 페이지 전환 모두에서 초기화한다.
- 중복 초기화를 막는 상태 속성을 둔다.
- 사용자 제공 문자열은 `innerHTML`이 아니라 `textContent`로 출력한다.

### 10.2 진도 저장

```text
localStorage key: ai-agent-book.course.v1
```

저장 대상:

- 방문한 모듈
- 완료한 모듈
- 최고 점수
- 시도 횟수
- 마지막 모듈
- 프로젝트 체크포인트

스크롤만으로 자동 완료하지 않는다. 퀴즈 기준 충족 또는 명시적인 완료 동작으로 기록한다.

### 10.3 접근성

- 퀴즈는 `fieldset`, `legend`, 명시적 레이블을 사용한다.
- 결과 메시지는 `aria-live`로 알린다.
- 색상만으로 정답과 오답을 구분하지 않는다.
- 모든 인터랙션은 키보드로 조작 가능해야 한다.
- 포커스 표시를 제거하지 않는다.
- 모바일에서 가로 스크롤 없이 핵심 기능을 사용할 수 있어야 한다.

## 14. 가독성과 학습 품질 목표

- 평균 문장 길이: 25~32자
- 300자 이상 문단: 전체의 3% 이하
- 한영 병기: 모듈당 3~5회 이하
- 굵은 강조: 500자당 한 번 이하
- 첫 퀴즈 평균: 70% 이상
- 해설 후 재시도: 85% 이상
- 명확성 평가: 5점 만점에 평균 4점 이상
- 과정 완료율: 80% 이상
- 실제 소요 시간: 예상 시간의 ±25% 이내

파일 완성만으로 학습 품질을 판정하지 않는다. 1모듈 완성 후 먼저 소규모로 학습 흐름을 검증하고, 결과를 반영한 뒤 나머지 모듈의 표현과 인터랙션을 통일한다.
