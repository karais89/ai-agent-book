# 10장 · 멀티 에이전트 협업

> 집단 지능은 개별 지능을 넘어설 수 있다. 멀티 에이전트 분류 프레임워크, 실제로 단일 에이전트보다 뛰어난 경우, 컨텍스트를 공유하거나 공유하지 않는 협업, 실패 모드, 새롭게 등장하는 ‘에이전트 사회’를 다룬다.

← [메인 README로 돌아가기](../README.md) · 📖 [장 본문 읽기](../book/chapter10.md)

## 부속 프로젝트

| 실험 | 프로젝트 | 유형 | 설명 |
| :--: | --- | :--: | --- |
| 10-1 | [staged-system-prompt](staged-system-prompt/) | ✅ | 같은 코딩 에이전트가 작업의 실행 단계(요구사항 명확화 → 코드 구현 → 코드 검토)에 따라 서로 다른 시스템 프롬프트와 도구 집합을 로드한다. 한 대화 안에서 여러 역할을 맡고 서로 다른 행동을 보이면서도 대화 기록과 작업 상태는 단계 사이에서 계속 공유된다. 검토에 실패하면 구현 단계로 돌아갈 수 있다. |
| 10-2 | [multi-role-transfer](multi-role-transfer/) | ✅ | 공유 컨텍스트 안의 연쇄 핸드오프를 보여 준다. 한 세션에 각자 고유한 시스템 프롬프트와 전용 도구 집합을 가진 전문 역할 에이전트 여러 개가 들어 있다. 에이전트는 `transfer_to_agent` 도구로 작업 진행 상황에 따라 다른 역할로 전환할 시점을 자율적으로 결정한다. 같은 대화 기록을 공유하므로 핸드오프 과정에서도 전체 컨텍스트가 자연스럽게 보존된다. |
| 10-3 | [book-translation](book-translation/) | ✅ | 오케스트레이터 방식으로 긴 문서 번역을 용어집·번역·교정 전문 에이전트에게 나눈다. 관리자는 작업, 계획, 호출 기록, 파일 인덱스만 저장하고 번역문 전체는 디스크에 기록하여 컨텍스트 크기를 거의 일정하게 유지한다. 단일 에이전트 방식과 비교하고 실제 토큰 수로 컨텍스트 폭증을 제어하는 법과 공유 용어집으로 책 전체의 일관성을 확보하는 법을 보여 준다. |
| 10-4 | `use-computer-while-calling/` | 📖 | 전화 에이전트와 컴퓨터 사용 에이전트로 이루어진 이중 에이전트 협업 아키텍처를 구현한다. 두 에이전트는 조정자 없이 WebSocket으로 직접 통신한다. 전화 에이전트가 음성 상호작용을 맡고 컴퓨터 에이전트가 브라우저를 자동화하여 음성과 웹 작업이 모두 필요한 복잡한 업무를 병렬로 처리한다. 코드는 독립적으로 관리되는 [TalkAct](https://github.com/19PINE-AI/TalkAct)로 발전했으며, 이 저장소에는 해당 디렉터리가 없다(복제 명령은 메인 README 부록 참고). |
| 10-6 | [parallel-web-research](parallel-web-research/) | ✅ | 중앙 조정 아래 동질적인 여러 에이전트가 병렬 검색하는 방식을 보여 준다. 주 조정자가 N개의 하위 에이전트를 동시에 시작하고 각 에이전트는 한 정보원에서 답을 찾는다. 하나가 목표를 찾으면 나머지는 안전하게 종료한다. 메시지 버스, 병렬 배분, 실시간 모니터링, 연쇄 종료, 경쟁 상태 처리를 현실적으로 구현하며 실제 브라우저 대신 제어 가능한 모의 정보원을 사용한다. |
| 10-7 | `generative_agents/` | 📖 | Stanford의 ‘AI 마을’ 생성형 에이전트(실험 10-7 부속 프로젝트)다. 외부 저장소 `joonspk-research/generative_agents`를 직접 복제해야 한다(메인 README 부록 참고). |
| 10-8 | [voice-werewolf](voice-werewolf/) | ✅ | 멀티 에이전트 늑대인간 게임으로 ‘비공유 컨텍스트’의 정보 접근 제어를 보여 준다. 각 플레이어는 엄격하게 격리된 비공개 컨텍스트를 가진 독립 LLM 에이전트다. 코드 기반 결정론적 심판이 어느 정보를 어느 플레이어의 컨텍스트에 전달할지 결정하고 감사를 위해 기록하며, 게임이 끝나면 격리가 올바른지 자동 검증한다. 음성은 선택 기능이다. |
