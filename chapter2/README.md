# 2장 · 컨텍스트 엔지니어링

> 컨텍스트는 에이전트 능력의 상한을 결정한다. LLM API의 컨텍스트 구조, KV 캐시에 유리한 설계, 프롬프트 엔지니어링, 동적 프롬프트와 에이전트 스킬, 상태 표시줄의 메타 정보, 컨텍스트 압축 전략을 깊이 살펴본다.

← [메인 README로 돌아가기](../README.md) · 📖 [장 본문 읽기](../book/chapter2.md)

## 부속 프로젝트

| 실험 | 프로젝트 | 유형 | 설명 |
| :--: | --- | :--: | --- |
| 2-1 | [local_llm_serving](local_llm_serving/) | ✅ | 가장 적합한 백엔드(vLLM 또는 Ollama)를 자동으로 선택하는 크로스 플랫폼 로컬 LLM 배포 솔루션이다. 시스템을 잘 설계하면 0.6B 소형 모델도 뛰어난 도구 호출 능력을 보일 수 있음을 보여 주며, 사고 과정을 실시간으로 표시하는 스트리밍 응답을 지원한다. |
| 2-2, 2-7 | [attention_visualization](attention_visualization/) | ✅ | LLM의 전체 입출력 토큰 시퀀스와 어텐션 가중치 분포를 시각화하여 모델이 컨텍스트를 처리하고 사고하며 도구를 호출하는 방식을 깊이 이해하도록 돕는다. |
| 2-3 | [kv-cache](kv-cache/) | ✅ | 서로 다른 컨텍스트 관리 방식이 KV 캐시에 미치는 영향을 탐구하고 흔한 오류 패턴이 캐시 효율을 어떻게 파괴하는지 보여 준다. 올바른 컨텍스트 설계로 지연 시간과 비용을 크게 줄일 수 있음을 실험으로 확인한다. |
| 2-4 | [prompt-engineering](prompt-engineering/) | ✅ | Tau-Bench 프레임워크를 확장해 체계적인 제거 실험으로 여러 프롬프트 엔지니어링 요소가 에이전트 성능에 미치는 영향을 정량화한다. 어조, 지시 구성, 도구 설명 같은 요소가 작업 완료율에 어떤 영향을 주는지 보여 준다. |
| 2-5 | [prompt-injection](prompt-injection/) | ✅ | 3가지 공격 시나리오(직접 인젝션, 간접 인젝션, 메모리 인젝션) × 4가지 방어 설정(방어 없음, 프롬프트 강화, 출처 태깅, 결합 방어)의 통제 실험을 구성한다. 결정론적 규칙으로 공격 성공률을 계산하여 계층형 방어가 성공률을 크게 낮추는 모습을 시각적으로 보여 준다. |
| 2-6 | [agent-skills-ppt](agent-skills-ppt/) | ✅ | 에이전트 스킬의 ‘점진적 공개’ 개념을 재현한다. 처음에는 에이전트가 간결한 스킬 디렉터리만 본다. 작업에 `pptx` 스킬이 필요하다고 판단한 뒤에야 전체 워크플로, 상세 문서, 번들 스크립트를 단계적으로 로드하고, 마침내 python-pptx로 실제 `.pptx` 파일을 만든다. |
| 2-8 | [system-hint](system-hint/) | ✅ | 시스템 힌트가 에이전트 행동에 미치는 영향을 연구하고 시스템 프롬프트 최적화로 성능을 높이는 방법을 탐구한다. |
| 2-9 | [context-compression](context-compression/) | ✅ | 요약, 핵심 정보 추출, 의미 압축을 비롯한 여러 컨텍스트 압축 전략을 구현하고 비교한다. 에이전트 능력을 유지하면서 토큰 사용량을 줄인다. |
| 3-3 | [log-sanitization](log-sanitization/) | ✅ | 디버깅에 필요한 정보를 보존하면서 민감한 데이터를 보호하는 지능형 로그 정제 시스템을 구현한다. |
