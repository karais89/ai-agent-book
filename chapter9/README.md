# 9장 · 멀티모달과 실시간 상호작용

> 인식과 행동을 텍스트에서 음성, GUI, 물리 세계로 확장한다. 세 가지 음성 패러다임(캐스케이드/엔드투엔드 옴니모달/전이중), 스트리밍 음성 인식과 합성, 컴퓨터 사용, 로봇 조작을 다룬다.

← [메인 README로 돌아가기](../README.md) · 📖 [장 본문 읽기](../book/chapter9.md)

## 부속 프로젝트

| 실험 | 프로젝트 | 유형 | 설명 |
| :--: | --- | :--: | --- |
| 9-1 | [live-audio](live-audio/) | ✅ | 음성 인식, AI 대화, 음성 합성을 통합한 실시간 음성 대화 데모다. 여러 AI 서비스 제공자(OpenAI, OpenRouter, ARK, SiliconFlow)를 지원하여 지연 시간이 짧은 대화 경험을 제공한다. |
| 9-2 | [phone-agent](phone-agent/) | ✅ | ‘사용자를 대신해 전화로 외부 세계와 상호작용하는’ 음성 에이전트를 보여 준다. 상위 계층은 표준 ReAct 에이전트다. 자연어 작업을 받으면 통화 횟수와 목적을 자율적으로 판단하고, 전화 API 추상화 기반의 `make_phone_call` 도구로 전체 대화를 마친 뒤 구조화된 통화 기록을 읽는다. 필요하면 다시 전화해 후속 질문을 하고 마지막에 사용자에게 결과를 보고한다. |
| 9-3 | [streaming-speech](streaming-speech/) | ✅ | 스트리밍 음성 인식의 핵심 상충 관계를 보여 준다. 연속 음성을 점차 길어지는 구간으로 나누어 ASR에 전달하고, 구간을 받을 때마다 ‘현재 부분 인식 결과’를 내놓아 첫 구간의 텍스트 출력 지연을 극도로 낮춘다. 대신 초기 구간에는 문장 후반의 컨텍스트가 없어 틀릴 수 있으며 음성이 쌓일수록 점차 올바른 결과로 수렴한다. 이는 ‘문장 전체를 받은 뒤 인식’하는 고정확도·고지연 방식과 대비된다. |
| 9-4 | [end-to-end-speech](end-to-end-speech/) | ✅ | Step-Audio R1의 엔드투엔드 음성 사고(‘듣기 → 생각하기 → 말하기’)를 ASR→LLM→TTS 직렬 구조와 비교하여 지연 시간과 준언어 정보 손실을 살펴본다. |
| 9-5 | [controllable-tts](controllable-tts/) | ✅ | 주 LLM의 출력에 감정, 말하기 속도, 스타일, 쉼, 웃음 제어 토큰을 넣는다. 실행 계층은 이를 해석하고 참조 음성 라이브러리의 스타일 프로필에 매핑해 음성을 합성한다. ‘어디에서 멈추고 어떤 어조를 쓸지’ 결정하는 일을 LLM에 맡겨 같은 텍스트를 여러 스타일과 감정으로 합성한다. |
| 9-6 | `claude-quickstarts/` | 📖 | 여러 사용 사례를 아우르는 Claude API 빠른 시작 예제와 모범 사례다. |
| 9-7 | `browser-use/` | 📖 | Browser-Use는 LLM이 브라우저를 제어해 복잡한 작업을 끝내도록 하는 강력한 브라우저 자동화 프레임워크다. 양식 입력, 웹 탐색, 데이터 추출 같은 시나리오를 지원하며 GUI 자동화(컴퓨터 사용)의 대표 구현이다. |
