# 과정 마무리

여기까지 왔다면 자연스러운 답변을 만드는 데서 한 걸음 더 나아갔다. 이제 모델의 제안, 코드의 실행, 환경의 실제 상태를 구분하고, 사고가 나기 전에 제약과 검증을 둘 수 있다.

아래 보드는 이 브라우저에 저장된 모듈 완료 상태와 퀴즈 기록을 보여 준다. 계정이나 서버와 동기화되지 않으므로 다른 기기에는 자동으로 이어지지 않는다.

## 완주 전 확인

아직 표시되지 않은 모듈이 있다면 해당 페이지로 돌아가 퀴즈 해설을 확인하고 완료 버튼을 누르자. 스크롤만으로는 완료 처리되지 않는다.

과정을 마친 학습자는 다음 질문에 자신의 말로 답할 수 있어야 한다.

1. 챗봇, 결정론적 워크플로, 에이전트는 언제 각각 알맞은가?
2. 모델의 도구 호출 요청과 실제 도구 실행은 어떻게 다른가?
3. 정적 지시, 동적 작업 상태, 외부 정책 자료는 왜 분리하는가?
4. 조회 도구와 상태 변경 도구에는 어떤 안전 차이가 있는가?
5. 사용자 확인, 멱등성, 사후 검증은 각각 어떤 실패를 막는가?
6. 최종 답변뿐 아니라 실행 흔적도 평가해야 하는 이유는 무엇인가?
7. 오래된 정책, 모호한 절차, 승인 우회는 각각 어디를 고쳐야 하는가?
8. 목표 사례가 좋아져도 전체 회귀 평가가 필요한 이유는 무엇인가?

답하기 어려운 항목이 있다면 실패가 아니다. 그 질문에 대응하는 모듈 한 개만 다시 실행하면 된다.

## 완성한 시스템

Mori Shop 주문·환불 지원 에이전트는 다음 경로를 갖게 되었다.

```text
요청
→ 주문·사유 확인
→ 시행 중인 정책과 금액 확인
→ 사용자 확인
→ 서버의 권한·불변조건 검사
→ 멱등한 환불 생성
→ 실제 상태 재조회
→ 검증된 결과만 보고
```

이 흐름에는 12개 고정 평가 시나리오, 네 가지 안전 출시 게이트, 변경 버전, 카나리와 롤백 판단도 포함된다. 상세 데이터와 도구 계약은 [누적 프로젝트 안내](project.md)에서 다시 볼 수 있다.

## 다음 학습 경로

원문을 처음부터 다시 선형으로 읽을 필요는 없다. 지금 해결하려는 질문에 맞는 장을 참고 자료처럼 고르면 된다.

- 에이전트 구조와 하네스를 더 깊게 설계하려면 [1장](../book/chapter1.md)과 [5장](../book/chapter5.md)을 읽는다.
- 컨텍스트, 검색, 사용자 메모리가 궁금하면 [2장](../book/chapter2.md)과 [3장](../book/chapter3.md)을 읽는다.
- 도구와 실제 실행 인터페이스를 확장하려면 [4장](../book/chapter4.md)과 부속 실험을 살펴본다.
- 평가와 운영 개선을 강화하려면 [6장](../book/chapter6.md)과 [8장](../book/chapter8.md)을 읽는다.
- 모델 학습이 정말 필요한지 판단하려면 [7장](../book/chapter7.md)을 참고한다.
- 역할 분리와 독립 검토가 필요할 때만 [10장](../book/chapter10.md)의 멀티 에이전트 구성을 검토한다.

전체 원문은 원리, 연구, 제품 사례, 실험이 함께 들어 있는 심화 참고서다. 코스에서 만든 Mori Shop 체크리스트를 옆에 두고 “이 내용은 내 시스템의 어느 층을 바꾸는가?”라고 질문하면 훨씬 수월하게 읽을 수 있다.

## 실제 프로젝트로 옮길 때

학습용 로컬 시나리오를 실제 서비스에 바로 연결하지 않는다. 먼저 조직의 정책 소유자, 권한 체계, 개인정보 보관 기준, 감사 로그, 장애 대응 책임자를 확인해야 한다. 샌드박스에서 읽기 전용 도구부터 연결하고, 상태 변경 도구는 서버 검사와 사람이 승인한 출시 게이트를 갖춘 뒤 제한된 범위에서 검증한다.

이 코스의 완료 표시는 학습 진도를 위한 로컬 기록이며 공식 수료증이나 운영 안전성 인증이 아니다. 실제 배포 판단은 서비스의 위험과 규정에 맞춘 별도 검토가 필요하다.
