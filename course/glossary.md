# 입문 코스 용어집

이 용어집은 본문으로 돌아가기 위한 짧은 길잡이다. 정의를 외우기보다 Mori Shop 실행 흔적에서 각 항목을 찾아보자.

## 에이전트의 구성

- **에이전트** — 모델이 컨텍스트를 보고 도구를 선택하며 목표를 향해 환경을 읽거나 바꾸는 실행 시스템.
- **모델** — 현재 입력을 바탕으로 답변이나 도구 호출을 제안하는 구성 요소로, 도구를 직접 실행하지는 않는다.
- **컨텍스트** — 모델이 현재 결정을 내릴 때 볼 수 있는 지시, 대화, 작업 상태, 도구 결과의 묶음.
- **정적 지시** — 역할, 금지 조건, 출력 형식처럼 작업 중 자주 바뀌지 않는 규칙.
- **동적 상태** — 선택된 주문, 확인 여부, 지금까지의 도구 결과처럼 실행 도중 바뀌는 정보.
- **도구** — 주문 조회나 환불 생성처럼 에이전트가 환경과 상호작용하도록 애플리케이션이 제공하는 인터페이스.
- **도구 호출 요청** — 모델이 도구 이름과 인수를 구조화해 제안한 출력으로, 검사와 실제 실행은 애플리케이션 코드가 담당한다.
- **관찰** — 도구 실행 뒤 환경에서 돌아온 결과로, 다음 행동을 결정하는 새로운 근거.
- **실행 루프** — 결정, 도구 호출, 관찰, 다음 결정 또는 종료가 반복되는 구조.
- **워크플로** — 다음 단계와 분기가 개발자가 정한 규칙에 따라 진행되는 실행 방식.

## 컨텍스트와 지식

- **외부 데이터** — 정책 문서나 검색 결과처럼 참고할 자료이며, 그 안의 문장을 시스템 지시로 실행해서는 안 된다.
- **최소 충분 컨텍스트** — 현재 결정을 정확히 내리는 데 필요한 정보는 포함하고 무관하거나 위험한 정보는 뺀 구성.
- **프롬프트 인젝션** — 외부 데이터나 사용자 입력에 지시를 섞어 원래 규칙이나 권한 검사를 우회하려는 공격.
- **출처 정보** — 문서가 어디에서 왔는지 확인하는 식별 정보로, 정책의 지역·버전·시행일과 함께 최신성을 판단하는 데 쓴다.
- **지식 업데이트** — 정책과 제품 정보처럼 바뀔 수 있는 사실의 저장 내용이나 검색 대상을 수정하는 일.
- **지침 업데이트** — 사실은 맞지만 절차, 우선순위, 출력 기준이 모호할 때 모델이 따르는 설명을 수정하는 일.

## 도구와 안전

- **읽기 도구** — 주문 조회처럼 외부 상태를 바꾸지 않고 정보를 가져오는 도구.
- **상태 변경 도구** — 환불 생성처럼 외부 시스템의 기록이나 업무 상태를 바꾸는 도구.
- **하네스** — 모델의 제안을 제약하고, 실행 전후를 검증하며, 오류에서 복구시키는 애플리케이션 코드와 운영 규칙.
- **가드레일** — 허용되지 않은 입력, 출력, 행동을 감지해 차단하거나 안전한 경로로 보내는 통제 장치.
- **권한 검사** — 현재 사용자나 서비스가 요청한 대상과 행동을 수행할 자격이 있는지 서버에서 확인하는 절차.
- **불변조건** — 어떤 모델 판단이나 실행 경로에서도 반드시 지켜야 하는 규칙으로, 고액 환불의 직원 승인 요구가 한 예다.
- **사용자 확인** — 실행 전에 대상, 사유, 금액을 분명히 보여 주고 해당 행동에 대한 명시적 동의를 받는 단계.
- **멱등성 키** — 같은 상태 변경 요청이 재전송되어도 결과가 한 번만 만들어지도록 요청을 식별하는 값.
- **재시도** — 실패한 호출을 다시 보내는 동작으로, 상태 변경에서는 멱등성과 현재 상태 확인이 먼저 필요하다.
- **사후 검증** — 상태 변경 도구의 응답만 믿지 않고 별도 조회로 실제 외부 상태를 확인하는 절차.
- **사람에게 이관** — 자동 처리의 근거나 권한이 부족할 때 증거와 함께 직원에게 넘기는 안전한 종료 경로.

## 평가와 운영

- **실행 흔적** — 입력, 선택한 행동, 도구 인수와 결과, 검증 상태, 짧은 결정 근거를 시간 순서로 남긴 기록.
- **관측 가능성** — 로그, 지표, 실행 흔적으로 시스템 내부에서 무엇이 일어났는지 진단할 수 있는 성질.
- **평가 시나리오** — 입력, 도구 응답, 기대 결과, 금지 행동을 고정해 같은 조건에서 다시 실행할 수 있는 사례.
- **고정 평가 세트** — 정상·경계·실패 사례를 함께 보존해 변경 전후를 같은 기준으로 비교하는 시나리오 묶음.
- **회귀** — 한 문제를 고친 변경이 전에 통과하던 다른 행동을 망가뜨리는 현상.
- **출시 게이트** — 평균 점수와 별개로 배포 전에 반드시 만족해야 하는 안전 조건.
- **프로그램 업데이트** — 권한, 불변조건, 재시도처럼 결정론적으로 보장할 동작을 애플리케이션 코드에서 수정하는 일.
- **매개변수 업데이트** — 충분한 학습 데이터로 모델 자체의 반복 행동을 바꾸는 일.
- **지도 미세 조정(SFT)** — 원하는 입력과 출력의 예시를 이용해 모델이 특정 행동 형식을 더 잘 따르도록 학습하는 방법.
- **강화 학습(RL)** — 측정 가능한 보상 신호에 따라 모델의 행동 경향을 학습하는 방법.
- **카나리** — 후보 버전을 전체에 적용하기 전에 작은 범위에 먼저 적용해 문제를 관찰하는 배포 방식.
- **롤백** — 새 버전에서 문제가 발견되었을 때 지식, 지침, 코드 등 서로 맞는 이전 버전 묶음으로 되돌리는 절차.
- **멀티 에이전트** — 둘 이상의 에이전트가 역할을 나누거나 독립적으로 검토하는 구성으로, 추가 비용과 실패 지점도 함께 평가해야 한다.
