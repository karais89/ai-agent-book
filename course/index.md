# AI 에이전트 입문 코스

긴 원문을 처음부터 끝까지 읽지 않아도 괜찮다. 이 코스는 Python과 JSON의 기초만 아는 개발자가 작은 에이전트를 직접 설계하고, 안전성과 평가 방법까지 익히도록 안내한다.

필수 과정은 브라우저 안의 결정론적 시나리오로 진행한다. 실제 LLM API 키나 결제·환불 계정은 필요하지 않으며, 외부 서비스의 상태에도 영향을 주지 않는다.

## 먼저 10분만 투자하기

[10분 핵심 개요](00-overview.md)에서 챗봇, 워크플로, 에이전트의 차이를 확인하고 전체 학습 지도를 살펴보자. 이미 에이전트의 실행 루프를 알고 있다면 [1모듈](01-agent.md)부터 시작해도 된다.

## 하나의 프로젝트를 여섯 번 개선한다

과정 내내 **Mori Shop 주문·환불 지원 에이전트**를 사용한다. 첫 모듈에서는 주문을 읽는 최소 루프를 만들고, 마지막 모듈에서는 고정 평가 세트와 롤백 절차를 갖춘 시스템으로 발전시킨다.

| 모듈 | 답할 질문 | 프로젝트 변화 |
| --- | --- | --- |
| [1. 에이전트와 실행 루프](01-agent.md) | 모델의 답변은 어떻게 행동으로 이어지는가? | 주문을 조회하고 멈출 줄 아는 최소 루프 |
| [2. 올바른 컨텍스트](02-context.md) | 모델에는 어떤 정보를 보여 줘야 하는가? | 정책의 출처·지역·시행일과 외부 데이터를 분리 |
| [3. 안전한 도구](03-tools.md) | 읽기와 상태 변경은 어떻게 나눠야 하는가? | 조회·견적·환불 실행 도구를 분리 |
| [4. 하네스와 안전성](04-harness.md) | 모델이 틀려도 사고를 막을 수 있는가? | 확인·멱등성·사후 검증·복구 절차 추가 |
| [5. 평가](05-evaluation.md) | 시스템이 실제로 좋아졌는지 어떻게 아는가? | 12개 고정 시나리오와 출시 게이트 추가 |
| [6. 운영 경험으로 개선](06-improvement.md) | 실패가 생기면 어디를 고쳐야 하는가? | 지식·지침·코드 변경과 카나리·롤백 적용 |

각 모듈은 25~35분 분량이다. 실패 장면을 먼저 보고, 결과를 예측한 뒤, 실행 흔적과 퀴즈로 이해를 확인한다. 완료 상태와 최고 점수는 현재 기기의 브라우저에만 저장된다.

## 이 코스가 다루지 않는 것

Transformer 내부 구조, 강화 학습 알고리즘, 벡터 데이터베이스, 분산 멀티 에이전트 구현은 필수 범위가 아니다. 과정 중 더 깊이 알고 싶은 주제만 전체 원문과 실험 링크로 이동하면 된다.

전체 이론을 먼저 살펴보고 싶다면 [1장 원문](../book/chapter1.md)을 이용하자. 빠르게 큰 그림을 잡고 싶다면 [10분 핵심](00-overview.md)부터 시작하면 된다. 입문 코스를 마친 뒤에도 원문 10장과 부속 실험은 그대로 참고할 수 있다.
